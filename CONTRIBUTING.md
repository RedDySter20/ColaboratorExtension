# Как участвовать в разработке

Спасибо за интерес к проекту. Ниже — короткий путь от клона репозитория до
принятого pull request'а.

## Требования

- Node.js **20+** (для тестов, линта и сборки).
- Chrome/Chromium/Edge **116+** для ручной проверки.
- Python 3 + Pillow — только если меняете иконки (`npm run icons`).

## Быстрый старт

```bash
git clone https://github.com/RedDySter20/ColaboratorExtension.git
cd ColaboratorExtension
npm ci
npm test          # ~90 юнит-тестов, браузер не нужен
npm run lint
npm run build     # dist/ + проверка manifest и графа модулей
```

Для ручной проверки: `chrome://extensions/` → режим разработчика →
«Загрузить распакованное расширение» → папка `src/` (или `dist/`).

## Что можно улучшить

- Новые протоколы в инспекторе (`src/js/core/protocol.js`).
- Поддержка других серверов коллаборации (`src/js/core/poller.js`).
- Улучшения UI/UX и доступности.
- Документация, примеры, переводы.
- Исправления ошибок с воспроизведением в issue.

## Правила кода

1. **`src/js/core/` не использует DOM и `chrome.*`** (исключение —
   `settings.js`). Всё, что можно проверить юнит-тестом, живёт там.
2. **Без новых рантайм-зависимостей.** Расширение должно оставаться загружаемым
   как есть, без бандлера.
3. **ES-модули, `const`/`let`, JSDoc-типы** в публичных функциях. Стиль
   фиксируется Prettier (`npm run format`), проверяется ESLint (`npm run lint`).
4. **Не меняйте алгоритм генерации идентификаторов** без необходимости: он
   закреплён golden-векторами в `tests/fixtures/golden.json`. Если изменение
   действительно нужно — обновите векторы и добавьте пометку в CHANGELOG.
5. Тексты интерфейса — на русском, идентификаторы и комментарии в коде — на
   английском.

## Тесты

- Новое поведение → новый тест. Для IndexedDB используется `fake-indexeddb`.
- Обязательный минимум перед PR:

  ```bash
  npm run lint && npm test && npm run build
  # или одной командой:
  npm run check
  ```

- Тесты запускаются в одном процессе (`--test-isolation=none`) — не полагайтесь
  на изоляцию глобального состояния между файлами; используйте `beforeEach` для
  очистки базы.

## Коммиты и PR

- Сообщения коммитов: `type(scope): краткое описание`, где `type` — один из
  `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `perf`.
  Пример: `feat(poller): поддержка interactsh AES-CTR`.
- Один PR — одна логическая тема; описывайте, что и зачем изменено, как
  проверяли, при необходимости прикладывайте скриншоты.
- Обновляйте `CHANGELOG.md` в разделе `Unreleased` для пользовательских
  изменений (новая функция, исправление, breaking change).

## Безопасность

Не создавайте публичные issue с реальными ключами сессий, приватными URL и
фрагментами чужих взаимодействий. Для уязвимостей самого расширения используйте
приватное сообщение мейнтейнеру.

Проект — инструмент для авторизованного тестирования. PR, добавляющие
возможности скрытого слежения, обхода авторизации на чужих сервисах или
автоматической эксплуатации, не принимаются.
